# Obsidian 1.15との互換性

対象環境はWindows・Obsidian 1.15.0以降です。同梱エンジンが既定で、組み込みVimは実験的な選択肢です。切り替えと設定の扱いは[README](../README.md#エンジンの選択)、実装の境界は[開発仕様](development.md#エンジンと寿命)を参照してください。

[公式の1.15変更履歴](https://obsidian.md/changelog/2026-11-02-desktop-v1.15.0/)にある各項目について、ObsidianとLindvimeraの担当を示します。「ホスト」はObsidianの機能をそのまま使うことを意味します。

## Vim・Exの仕様

| 操作               | 同梱エンジン                                                                                             | 組み込みVim                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `g?`               | ASCII英字のROT13変換。`g??`・`g?g?`、motion、Visual選択、`.`に対応します。                               | ホストのコアへ委譲します。                                                 |
| `:put`             | レジスタを行として挿入します。`+`の非同期クリップボード読込にも対応します。                              | ホストのEx処理へ委譲します。                                               |
| 検索による範囲指定 | `/pattern/`・`?pattern?`、空パターン、符号付きoffsetに対応します。本文または現在のセル内で折り返します。 | ホストの解析・検索状態を使います。                                         |
| `:set nopcre`      | Vim互換パターンへ切り替えます。`:set pcre`でJavaScript形式へ戻します。                                   | ホストの方言とオプションの寿命に従います。                                 |
| macOSのAlt割り当て | macOSは対応環境の対象外です。                                                                            | 同左。                                                                     |
| `gj`               | Live Previewの表示行とwidget座標へ移動します（通常時はadapterの表示行）。                                | Live Previewの表示行とwidget座標へ移動します（内蔵の`_x`スナップを抑止）。 |
| `:sort`            | 範囲指定、逆順、大小文字無視、数値順、重複除去に対応します。                                             | ホストのEx処理へ委譲します。                                               |
| Visualの`;`・`,`   | 文字検索の繰り返しで選択範囲を変更します。                                                               | ホストのコアへ委譲します。                                                 |
| Visualの`>`・`<`   | Markdown行編集とSmart Listsが有効な本文では、子項目を含む字下げをホストへ委譲します。                    | ホストのインデント処理を使います。                                         |

同梱エンジンの`:set`は`pcre`と`nopcre`だけに対応します。Vim互換形式は同梱コアの変換器によるもので、Vimの正規表現すべてを実装するものではありません。方言の設定はエンジンの一時状態で、エンジン切り替え時には移しません。片方の方言でしか使えないパターンを割り当てる場合は、その割り当て内で方言を明示してください。

置換文字列は両エンジンでJavaScript形式の`$1`〜`$99`・`$&`・`$$`を維持します。`nopcre`もパターンの意味だけを変更し、置換文字列の`\1`や単独の`&`にVimの意味を与えません。区切り文字、`\\`、`\n`、`\r`、`\t`のエスケープを使えます。空パターンは直前の検索、引数なしの`:s`は直前の置換を再利用します。

Exの対象は現在の本文またはセルです。隣接セルを検索・編集しません。確認中の`q`・Esc・Ctrl-c・Ctrl-[は確定済みの置換を残して終了し、マッピングの後続処理を再開します。対象文書の変更、競合による停止、エディタ破棄では保留中の処理を取り消します。

## 組み込みVimの拡張

レジスタ、標準移動、マクロ、検索、エディタごとのVim状態はホストが管理します。Lindvimeraは日本語・Markdown操作、再生成されるセルをまたぐマーク、入力待ちのヒントを追加します。Ex確認やセル復帰を待つ間は再生を保留し、完了後にホストの実行処理で続行します。マクロの挿入・置換・検索・矩形選択記録を保ち、ユーザーのレジスタを差し替えません。

折り畳みはマクロの実行順を維持するため、構文解析を同期的に最大100ms待ちます。必要な構文を取得できない場合は変更せず、再試行を案内します。大きな文書や編集直後ではこの制限が適用されます。

Smart ListsはObsidianの設定を参照し、プラグインのMarkdown機能設定から推測しません。設定の場所は[Obsidianの設定リファレンス](https://help.obsidian.md/settings)を参照してください。
